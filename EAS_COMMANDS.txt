 9) BEFORE A BUILD — quick project sanity checks
==============================================================================
   npx tsc --noEmit                 (types OK?)
   npx expo-doctor                  (SDK/package health)
   npx expo install --check         (list version mismatches)
   npx expo install --fix           (fix version mismatches, then commit)
   npx expo prebuild --no-install --platform ios   (reproduce EAS's prebuild
                                                     locally to catch config
                                                     errors before a cloud build)

 Commit any fixes BEFORE building — EAS builds from your git commits, not your
 unsaved working files:
   git add -A
   git commit -m "your message"

==============================================================================
 12) IF A BUILD CRASHES ON LAUNCH — how to get the real reason
==============================================================================
 On the iPhone:
   Settings -> Privacy & Security -> Analytics & Improvements
     -> Analytics Data -> find "Mator-<date>.ips" -> copy the top ~15 lines
       (exception type + first stack frames).
 Then check package health:  npx expo-doctor   and   npx expo install --check
 (Version mismatches and bad patch-package patches are common crash causes.)

==============================================================================
 ANDROID MAP KEY (delivery location picker)
==============================================================================
 The Android map needs a Google Maps key at build time. iOS uses Apple Maps and
 needs none. Set it as an EAS environment variable, for each profile that builds
 Android:

   eas env:create --name GOOGLE_MAPS_ANDROID_API_KEY --value <key> --visibility sensitive

 The key is baked into the build, so treat it as public: restrict it in Google
 Cloud to the package com.mator.myapp and the app's signing certificate, and set
 a quota. Without it the Android build offers address search instead of the map.
