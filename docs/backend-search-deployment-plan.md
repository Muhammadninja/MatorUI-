## Выполнение после подтверждения плана
1. Создать новый release-каталог, сохранить старый release/compiled dist и путь его PM2 config для отката. Точные абсолютные пути заполняются после preflight; in-place очистка текущего каталога не допускается.
2. Доставить исходники строго целевого SHA, проверить контрольную сумму и состав. Не копировать .local, .env, секреты, локальные БД/seed или macOS node_modules. Существующий серверный env подключить штатным способом без изменения значений.
3. В новом release/Backend выполнить `npm ci`, `npx prisma generate`, профильные search tests и `npm run build`. Не выполнять проверочный скрипт с локальными fixture/DDL на production. До перезапуска старый процесс продолжает работать.
4. Выполнить `pm2 reload <NEW_RELEASE>/Backend/ecosystem.config.js --env production`, сохраняя fork/1. Не создавать параллельный backend с тем же Telegram bot. Проверить, что процесс действительно использует новый release и целевой SHA.
5. Сразу проверить readiness/liveness, статус и счётчик перезапусков PM2. Не печатать сырые логи с данными аккаунтов.

## Проверка после deployment
- Публичный полный каталог читается двумя/несколькими страницами и служит oracle для текущих цен/рейтингов/номеров.
- OEM и GM: каждый реально существующий номер возвращает ожидаемый ID; регистр и разделители нормализуются. Если GM-номеров в каталоге нет, production GM-проверка отмечается как недоступная, а не заменяется тестовым товаром.
- price_asc/price_desc, rating/newest: правильный порядок; равные значения не дают пропусков/дублей при переходе страниц.
- under_1k: <1000 UZS; 1k_to_10k: >=1000 и <=10000; over_10k: >10000. Rating 3_plus/4_plus: оценка товара >=3/4, null исключён. Ожидаемые ID вычисляются из текущего публичного каталога. Если в реальных данных нет точных 1000/10000/3/4, эти точные границы остаются подтверждёнными локальными тестами; production данные ради проверки не добавляются.
- `ый`, limit=20: все ожидаемые ID, включая следующую страницу; полные обходы relevance/price_asc/price_desc без повторов и пропусков; неверный/чужой pageToken и неверные filters/sort возвращают 400.
- Native UI на api.mator.uz: OEM/GM при наличии данных, текстовый поиск, фильтры, загрузка следующих результатов и карточки. Существующий аккаунт, корзина, Garage и избранное сохраняются. Заказы/платежи не запускать.
