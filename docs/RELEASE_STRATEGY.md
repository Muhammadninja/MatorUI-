# Mator.uz — Стратегия подготовки к релизу (с реальными данными)

_Документ живой. Обновлять по мере закрытия пунктов._

---

## TL;DR
Технически приложение и бэкенд **почти готовы**. Релиз держат три вещи:
1. **Реальный каталог данных** (главный блокер — сейчас 44 демо-позиции).
2. **Два инженерных хвоста**: онлайн-оплата (Payme endpoint) + Terms (юрревью).
3. **Раскатка в сторах** (App Review / Google Play Production).

Критический путь: **наполнить прод реальным каталогом → раздать билды тестерам → выкатить в прод.**

## Фаза 1 — ДАННЫЕ (главный блокер, ~80% работы) 🔴
Именно из-за этого «ничего нет»: в базе 44 демо-детали и 3 марки.

### 1.1. Собрать реальные прайсы от поставщиков/дилеров
Формат (Excel/CSV), колонки:
`название · бренд · модель(и) · подкатегория (slug) · OEM+кросс-коды · цена (сум) · остаток · фото`
Источник OEM-кроссов: каталоги поставщиков, TecDoc, GM EPC.

### 1.2. Приоритизация (не всё сразу — по спросу)
- **Модели:** Cobalt, Gentra, Nexia, Spark, Damas → затем Tracker, Malibu, Onix, Captiva, Lacetti.
- **Категории:** сначала расходники/ходовка (см. файл `LAUNCH_CATALOG_MUST_HAVE.md`) — это ~80% заказов.
- Цель к запуску: **топ-моделей × топ-категорий с РЕАЛЬНЫМИ данными**, а не 520 пустышек.

### 1.3. Загрузка
Заполнить `oem-catalog-skeleton.csv` (или свой прайс в том же формате) → `npm run seed:oem:csv`.
Идемпотентно, с fit-строками → сразу на витрине и в поиске по артикулу.

### 1.4. Reference-данные
Сейчас `/v1/reference/makes` = 3 марки. Досеять реальный модельный ряд Chevrolet (минимум) + другие марки UZ-рынка. 52 подкатегории — готовы.

### 1.5. Контроль качества
Сверка OEM-номеров, актуальные цены, реальные фото (сейчас пусто → показывается плейсхолдер).

## Фаза 3 — Инженерные хвосты (быстрые) 🟡
1. **Payments mismatch:** клиент шлёт `POST /v1/orders/:id/payment`, бэкенд ждёт `POST /v1/payments/payme/invoices` (+ `/click/invoices`). Онлайн-оплата **не сработает** (fail-open → «оплата при получении»). Фикс = перенаправить клиент на реальный endpoint (1 файл). Нужен, если хочешь картой на старте.
2. **Terms & Conditions:** юрревью + заполнить 3 плейсхолдера (юрлицо, дата, контакт поддержки).
3. **Force-update:** `/v1/app/config` есть на бэке — проверить, что клиент его дёргает.
4. **Инфра:** `api.mator.uz` DNS→бокс + валидный cert; бэкенд задеплоен последним кодом.

## Фаза 4 — Раскатка в сторах 🟢
- **iOS:** build 41 → TestFlight → внутренние тестеры → внешние (beta review) → прод (App Review ~1–3 дня).
- **Android:** v7 → Internal testing (сейчас draft — нажать «Rollout») → Closed testing → Production.
- ⚠️ Оба билда смотрят на прод `api.mator.uz` → **каталог должен быть наполнен ДО раздачи тестерам**, иначе тестеры увидят пустоту.

## Критический путь
```
РЕАЛЬНЫЙ КАТАЛОГ (Фаза 1) ──▶ наполнить прод ──▶ раздать билды тестерам ──▶ App Review / Play ──▶ ПРОД
        ▲
   код (клиент+бэкенд) — по сути готов; хвосты (оплата, Terms) параллельно
```

## Роли
- **Ты / поставщики:** реальные прайсы, OEM-кроссы, цены, фото (Фаза 1).
- **Бэкенд:** импорт CSV, reference-данные, payments-фикс, деплой.
- **Клиент:** payments-фикс (1 файл), сборка/раскатка билдов.
- **Юрист:** Terms.
